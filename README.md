# PayProof

**Shareable, non-custodial Solana invoices with on-chain payment matching.** A seller creates an invoice for SOL or Devnet USDC. The buyer pays the seller's wallet directly. PayProof matches the transaction's unique reference, recipient, token and exact balance increase, then presents a printable payment record with the transaction signature.

This is a hackathon prototype for **test coins only**. Devnet and Testnet SOL have no monetary value. Do not use it for customer payments.

## What works

- Create a Devnet or Testnet invoice and share its `/invoice/<id>` URL. The invoice opens on another device when the app is publicly hosted.
- Pay a SOL invoice through the Phantom Chrome extension or open its Solana Pay link in a compatible wallet. The wallet must use the invoice's network.
- Check a payment using Solana RPC at `confirmed` commitment. SOL and USDC are checked in integer base units; Devnet USDC verification is covered by mock transaction tests, not a live token payment.
- Open the matching transaction in Solana Explorer and print or save the invoice's payment record as a PDF. This record is generated by the browser; it is not a signed document or an attestation.
- Optionally enter a USD amount to calculate SOL using a recent CoinGecko quote. If the price service fails, the app asks for a manual SOL amount and never substitutes a price.

A [Testnet SOL payment through Phantom on the current build](https://explorer.solana.com/tx/5Py8ceGwfPGi1bHGLFdmP7LNNuKQLxmP5dLgdZg8UMFDiaFbbUGX6M1jp2gZayGuew4P9huoe25aL2aYZRNEnSGm?cluster=testnet) was matched to its invoice on October 11, 2026. The hosted flow still needs testing.

## Run locally

Requires Node.js 20 or newer. The application itself has no package installation step.

```sh
node server.js
node --test
```

Open <http://localhost:3000/>. The automated suite currently has **18 passing tests**. The live Devnet test procedure and earlier results are in [DEVNET_TEST.md](DEVNET_TEST.md). A localhost invoice link works only on the same computer.

## Public demo deployment

For a **temporary, no-card demo**, use the default [render.yaml](render.yaml) Blueprint in Render. It uses public Devnet and Testnet RPC endpoints and Render's Free web service. Free services sleep after inactivity, and their local invoice data disappears on sleep, restart or redeploy. Create fresh invoices shortly before a demo; do not rely on old invoice URLs surviving. Public RPC endpoints can also rate-limit requests.

The alternative [paid Render Blueprint](render-paid.yaml) specifies a web service with a persistent disk. Render's free web service cannot attach one. Set `PAYPROOF_RPC_URL` and `PAYPROOF_TESTNET_RPC_URL` to your own reliable RPC endpoints before recording a public demo. `PAYPROOF_DATA_DIR` points to the mounted disk; without persistent storage, invoices disappear on restart or redeploy. Railway or another host can use the same environment variable with its own persistent volume.

The JSON invoice store is designed for one server instance. The server applies in-memory limits to invoice creation and payment verification, plus a short per-invoice RPC cooldown. These are demo safeguards, not seller authentication or production abuse protection. `PAYPROOF_CREATE_PER_HOUR`, `PAYPROOF_VERIFY_PER_MIN` and `PAYPROOF_VERIFY_MIN_INTERVAL_MS` tune them; `PAYPROOF_TRUST_PROXY=1` should be set only behind a trusted proxy.

## Limits and next steps

- QR codes are generated locally as SVG images; the payment link is not sent to an image service. The vendored generator in `vendor/qr.cjs` derives from Project Nayuki's MIT-licensed QR Code Generator.
- There is no seller authentication, invoice expiry, or production database. Invoice URLs are public to anyone who knows the ID.
- There is no verified live USDC payment or mainnet payment. No mainnet invoice option is exposed in the app.
- An experimental Devnet SOL Action endpoint and `dial.to/devnet` link are included. The endpoint has automated tests, but the hosted Blink and wallet signing flow have not been tested. Unfurling on X requires separate Dialect registration. Telegram Mini App is not integrated.
- The browser-generated payment record shows the RPC-matched transaction; it does not verify an SPL Memo or provide cryptographic proof of the PDF itself.

## Hackathon context

PayProof targets freelancers who need to associate an incoming wallet transfer with a specific job and share a readable payment record. Its current implementation demonstrates this narrow workflow; it does not yet establish a defensible advantage over existing crypto invoicing products.
